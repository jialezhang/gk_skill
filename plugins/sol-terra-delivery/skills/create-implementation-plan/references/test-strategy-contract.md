# 风险驱动测试与候选版本证据合同

## 两类对象必须分开

- **验收声明（Claim）**描述必须被证明的产品结果，用 `AC-*` 标识。
- **执行场景（Scenario）**描述一次实际测试操作，用 `SC-*` 标识。

一个执行场景可以证明多个验收声明。不得因为多个声明共享同一路径，就复制相同的浏览器操作、构建或 Provider 调用。

## 三档测试

| 档位 | 触发条件 | 内容 | 运行时机 |
| --- | --- | --- | --- |
| `fast` | 每次局部编辑 | 受影响的 focused test、必要静态检查、diff check | 高频 |
| `change` | 一个行为切片或边界完成 | 受影响模块的集成检查、阶段真实用户旅程、必要 Provider mock/sandbox | 检查点前 |
| `full` | 候选版本冻结、共享基础设施变化或明确高风险 | 完整回归、构建、跨目标验收 | 同一候选版本原则上一次 |

每个任务必须声明 `test_level`、变更风险、影响面和失效键。选择 `full` 时必须写明不可由 `fast`/`change` 覆盖的理由。代码审查、验收或模型切换本身不是重跑测试的理由。

## 阶段真实用户旅程

在每个用户可见阶段完成后，用真实入口、真实页面和真实交互运行最小完整旅程。它必须让首次使用者识别：

1. 当前任务；
2. 用户改变了什么；
3. 系统给出了什么结果；
4. 证据在哪里；
5. 下一步可以做什么。

需要付费或慢速 Provider 时，优先在早期阶段使用 `mock` 或 `sandbox` 证明交互和状态合同；只在候选版本的关键 Provider 边界使用最少量 `real_expensive` 调用。视频等高成本生成默认不进入常规回归。

## Provider 模式和成本门禁

允许模式：

- `mock`
- `sandbox`
- `real_free`
- `real_expensive`
- `not_applicable`

`real_expensive` 必须声明预算、最大调用次数、终止条件和替代证据。生成测试矩阵前先报告实际场景数与变体数；同一基础设施原因连续失败三次后停止剩余运行并先诊断共享故障。

## 组合测试约束

不要默认展开 UI × Provider × 恢复方式 × 浏览器的笛卡尔积。只有存在已识别的交互风险时才允许 `Matrix type: cartesian`，并必须给出：

- `Interaction risk`
- `Pairwise insufficient because`
- `Estimated executions`
- `Budget`

否则使用代表性场景、pairwise 或按风险抽样。

## 候选版本与证据复用

所有可用于完成声明的证据必须绑定到同一 `candidate.commit_sha`。每项证据记录：

- 命令或用户操作；
- 目标身份；
- Provider 模式；
- 运行者和模型；
- 时间；
- 结果与原始证据路径；
- 失效键。

仅当候选 commit、构建、Feature Flag、Provider 配置、数据库 schema/fixture、入口/API 或相关环境发生变化时，证据才失效。审查者应消费现有有效证据，只补缺口；不得为了“自己也跑过”而重复完整测试。

最终验收由未参与实现的 Terra 线程独立执行，并只在同一候选版本的声明覆盖、完整回归和原始证据均有效时签发 `TARGET_VERIFIED`。
