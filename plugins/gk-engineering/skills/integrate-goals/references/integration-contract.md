# Integration Contract

## Source identity

Pin the approved base commit and every Goal's remote branch and commit. Confirm all Goals share the intended repository and plan revision. A local directory name or branch label is not sufficient identity evidence.

Before merging, confirm each Goal's handoff identifies accepted evidence records and a completion telemetry snapshot. A child Goal's runtime provenance is scoped to that Goal branch and must be re-established after integration.

## Conflict ownership

Terra may resolve mechanical and local implementation conflicts that preserve approved contracts. The current main planning agent handles evidence that invalidates the plan, architecture, or high-risk security boundary, preferring Sol and otherwise using `sol_route_fallback`. Product outcome changes return to the user.

## Verification layers

After each dependency wave, run the affected integration boundaries. On the final clean commit run the full approved checks and exact-target journeys. A Goal-level pass cannot substitute for integrated evidence.

Any merge, resolved conflict, consumed-contract revision, or target-environment change triggers evidence-lifecycle reconciliation. Mark stale or invalidated evidence explicitly, then execute only the missing proof on the integrated candidate.

## Program evidence

The handoff maps every Goal to session, worktree, branch, clean commit, checkpoint reports, routing log, verification, evidence lifecycle, runtime provenance, completion telemetry snapshot, and integration result. Aggregate model/stage token usage only from runtime telemetry; label gaps as unavailable. Capture the Program completion telemetry snapshot before its terminal Goal transition.
